# 第一階段補充故障對照（確認收集後執行）

在同一受保護 VM、同一新版本目錄，沿用凍結的量測程式。只新增測試，不修改三次確認開機規約或實作。各案例結果保存到獨立 JSON，不併入確認樣本數。

1. 核心表容量設定改為非法值 3、C 仍為 256：實際設定不一致且更新失敗，必須 invalid。
2. 核心種子改成 SEED1 xor 1、C 維持原種子：必須 invalid，不能當成有效差異。
3. C 已完成後，刪除此 PID 的核心統計項目：這是受控 map 狀態注入，不是真正探針漏失；必須 invalid。
4. C 已完成後，將此 PID depth 設成 1：這是受控未配對狀態注入；必須 invalid。真正排程漏失仍由既有 maxactive 實驗提供證據。
5. 兩端一致設成 8 cells，以既有 getdents 隱藏模組產生 16 個差異項目：量測應有效、指紋應不同；若本次 IBLT 無法還原，警報仍須維持。記錄實際解碼結果，不推廣為一般容量保證。

前三種設定／狀態故障與最後一種合法但不足容量要明確區分。資料與失敗均保留。最後確認無研究模組殘留，核心／套件不變，計時器恢復。
