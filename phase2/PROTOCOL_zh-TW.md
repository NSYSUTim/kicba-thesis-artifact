# 第二階段：適用條件與保留同次證據的成本改良

2026-10-23。使用者已核准沿既定第二階段完成；不是重新開啟第 4、5 項或第三階段。執行前先保存本規約、來源與環境 SHA-256。先導修改保留版本與理由，確認收集另鎖版本。

## 研究問題與設計決定

1. 原來身分中的名稱、inode、型態是否確實各自參與判讀？新增、長短改名、只改 inode／型態應能在有效時判不同；重排應一致。這補原題的差異動作證據，不是擴大觀測範圍。
2. 正常動態目錄與 tmpfs 是否仍維持「同次列舉」的兩端一致？動態目錄不是兩次掃描快照，不能以變動為由直接容忍不一致。
3. 第三方實作能否在輸出確實被隱藏時量到差異？來源、移植修改與共用掛接元件均須揭露，不把不相容當偵測成功，也不冒稱完全獨立攻擊家族。
4. 合併每個程序的狀態／IBLT、減少逐項 map 查詢，能否在保持同次指紋、定位與失效規則下減少時間及配置？第一階段指出核心逐項路徑較昂貴，因此先選此方案；未選 fentry/fexit 是為保持已驗證的掛接與返回語意，未選延後解碼是因其約 2 ms 的時間不足以解決主要成本。

## 不變的範圍與保護

- 沿用專用單執行緒 C 掃描器的完整列舉；名稱、inode、型態；最外層 filldir64 返回 true 才計入。原版、第一階段與論文／簡報不修改。
- 程式及資料放 phase2/ 與來賓 /home/kicba/research_phase2_20261023/。新分支從第一階段 cb0a27a 延伸。原 main 與第一階段凍結來源逐檔驗證。
- 原 VM 不 update／upgrade／安裝套件。測試前 checkpoint，保存環境與更新計時器狀態；暫停後於結束恢復。不得覆寫 attempt、失敗或無效資料。
- 原 6.8 核心、ext4 加 tmpfs；另一核心採官方 Ubuntu 6.5.0-45-generic 套件的原 VM 複本，使用相同使用者空間。它是較舊核心的相容性對照，不宣稱驗證最新版。只在複本離線安裝指定核心及 headers，不全面升級。原機與同 IP 複本不能同時啟動。
- 不增加程式庫後邊界、第一端前視圖、一般程序監控、/proc、授權政策、rkchk 或外部時序重跑。本輪無法建立的環境須明列，不以未執行充當完成。

## 新儲存候選的契約

每個執行緒一筆預先建立的 map 值，含種子、cells、depth、pending、指紋、品質統計及最多 256 個 IBLT cell；每項入口／出口查此筆。上限 256 個登記執行緒，與原版 65,536 cell map 在每次 256 cells 時的理想併發容量對齊，不降低本輪測試的宣告併發數。登記、配置與清理時間計入另列；不能只報列舉時間。這是固定容量實作候選，不稱可免費擴表或按需建表。

狀態缺少、種子／cells 錯誤、讀名稱失敗、未配對、計數收支不符、返回探針窗口不明或 missed 增量非零一律 invalid。全域 missed 仍不能歸因單一 PID；入口 perf 探針統計仍不可見。IBLT 解碼失敗與差異警報分開，不放寬失效檢查來換取速度。

## 先導與確認

先導分別測原 6.8 及可用複本，確認新增變體能編譯、各動作實際發生、輸出與 oracle 正確、成本邊界一致。每個支援核心的確認採三個新 boot ID；先導與確認不混合。全部來源及參數須先鎖。

靜態適用矩陣：ext4／tmpfs，buffer 256／65536，原量測／合併候選，正常、重排、新增、變長改名、變短改名、inode-only、type-only、移除、既有 filldir 隱藏、既有等量替換、第三方隱藏，各 10 次／boot。注入器因緩衝區空間不足未變更時，記錄未執行；不得算成功陽性。大 buffer 的每種差異動作須有實際變更的有效正例。

各靜態狀態另保存無探針的真正輸出作干擾對照。第三方隱藏另檢查模組與探針兩種先後。oracle 由相同 fixture 的原始名稱位元組、inode、型態及指定變更建立；不拿偵測器自己解碼的結果當正解。

動態對照：兩種 FS、兩種 buffer、兩種量測，各 10 次／boot。背景反覆建立、改名、刪除專屬 churn 名稱，記實際操作數與每次掃描時段內的活動；無隱藏時預期有效一致。不能只證明背景程式存在，須證明掃描期間有變動。動態實收清單不是目錄某一瞬間的完整快照，故不與另一時刻清單硬比。

成本：512／8192／65536 項、無額外負載／2 個 CPU workers；解析基線、第一階段完整量測、合併候選三模式，同一 C binary、buffer 65536、cells 256、相同種子。每 boot 每條件 2 個暖機區組加 10 個主要隨機配對區組。記登記、掃描、讀回、解碼、清理與總時間，編譯／附掛另列。每 boot 報中位數、IQR、配對比值與跨 boot 變異，不將大量呼叫稱獨立環境。

品質控制：候選必須通過無效配置、缺少狀態、未配對、真實 maxactive=1 漏失、16 程序併發及合法小容量解碼失敗的控制。原版與候選的錯誤解碼成功須為 0；不只比摘要一致。

## 完成標準與停止條件

- 報告每個環境實測數、有效一致、有效不同、無效、還原正確／明確失敗／錯誤成功及未實際變更的分母。
- 有效靜態判讀、原始輸出與 oracle 相符；動態正常若出現差異，先查原因，不用容忍門檻遮掩。
- 合併候選在每個 65536 項主要無額外負載 boot 的配對中位數比值須小於 0.9，且品質無回退，才建議採用。未達也如實完成候選評估，不硬宣稱優化成功。不同核心分開判讀。
- 報固定邏輯資料量與全域 map 的 fdinfo memlock 指標，不能將其混稱整個工具的實體峰值記憶體。
- 結束恢復原 VM 的核心、套件與計時器，卸除測試模組與探針，校驗所有原鎖定檔。資料封存 SHA-256、本機提交，先不改論文／簡報、不推送，停止在第二階段。
