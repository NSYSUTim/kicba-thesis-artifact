# 跨層目錄項一致性檢查的目前方法與下一步

更新日期：2026-10-20。本文依目前論文 `eBPF_最終繳交.docx`、原始碼及既有結果整理。後續工作是建議，尚未執行或鎖定為新實驗規約。

目前已建立從核心端接受項目到使用者端完整列舉的身分比對流程，並在單一虛擬機的受控矩陣中驗證正確性。接下來最需要的證據，是不同環境與獨立隱藏實作下是否仍能可靠觀測，以及失去觀測能力時能否明確回報；大目錄成本則是實用化的另一個主要問題。

## 目前的方法

### 比較的對象

比較同一次完整列舉的兩份多重集合：核心端 `filldir64` 已接受的目錄項，以及使用者端從全部 `getdents64` 分頁收到的目錄項。每筆身分由名稱位元組、inode 與型態構成。這是在單次列舉內比較相鄰觀測層，不需讀原始磁碟。

核心端在進入函式時暫存項目，在返回時只計入最外層且回傳 `true` 的呼叫。這處理兩種情形：巢狀包裝不能重複計數，緩衝區不足而回傳 `false` 的項目不能當成已接受。使用者端持續呼叫 `getdents64` 到回傳 0，避免只拿第一頁比較。

控制程式為每次列舉啟動新量測行程，先登記 PID，再送啟動訊號；兩端使用相同種子與容量，列舉結束後依 PID 配對。

### 指紋與 IBLT 的分工

兩端同時建立指紋與 IBLT。指紋為 `F = (n, A, B)`：`n` 是項目數，`A` 與 `B` 是兩個 64 位元雜湊總和，依 64 位元溢位取餘數。加總與順序無關，也保留項目出現次數。移除一項會改變數量；等量替換保持數量，仍通常會改變雜湊總和。

指紋是機率式摘要，不能把兩份內容一致的摘要視為數學上的完全相等證明。現有 FNV-1a 與混合函式沒有對主動碰撞的密碼學保證，兩個總和也未證明獨立，不能宣稱有 128 位元安全強度。

IBLT 的兩張表相減後抵銷共同項目，再剝離可辨識的單一項目，還原核心端獨有及使用者端獨有的識別值、inode、型態，不還原名稱。正式設定為 256 個儲存格，預留最多 32 個差異項目的八倍容量；16 個名稱替換會在兩端各產生 16 個獨有項目。

| 量測與摘要狀態 | 目前輸出與意義 |
|---|---|
| 量測無效或行程失敗 | 無效或拒絕判定，不能算成一致或警報 |
| 量測有效、指紋相同 | 這次未觀察到範圍內的身分差異 |
| 指紋不同、IBLT 完整解碼 | 警報，附兩端獨有項目的識別值、inode 與型態 |
| 指紋不同、IBLT 解碼失敗 | 警報仍成立，標示無法完整還原；部分結果不當成完整差集 |

目前檢查包含種子與容量設定、名稱讀取及長度、核心資料表更新、進入與返回配對及接受項目數等。控制程式也拒絕缺少核心紀錄或異常終止的行程。更底層的 kretprobe `nmissed` 尚未納入。

### 威脅模型

範圍從 `filldir64` 接受項目之後，到 `getdents64` 結果交給使用者之前。項目在進入前被排除，兩端就不會有差異；過濾導致提早回傳 0 時，其後未走訪的項目也不在範圍內。

假設攻擊者無法控制 eBPF、量測程式與控制程式，且不針對量測器調整行為。正式種子由固定起始值與開機編號決定並寫入資料，可重現而不是祕密金鑰。目前未驗證能讀種子、改動量測點或辨識量測行程後選擇性放行的核心攻擊者。

警報只說明兩端不一致。授權政策過濾在主要評估中也是預期差異；進一步判斷惡意，需額外的授權、來源或完整性證據。

## 已完成與尚缺的證據

| 面向 | 已有證據 | 尚缺的證據 |
|---|---|---|
| 正式流程正確性 | 九次開機、1,296 批、25,920 次列舉；576 差異批全檢出，720 對照批零誤報 | 其他核心、檔案系統與獨立隱藏模組的正式矩陣 |
| 等量替換 | 144 批均檢出；只比數量全部漏掉 | 不同替換方式、差異量與主動碰撞 |
| 差異定位 | 11,520 次正式差異列舉全部精確還原 | 新環境中的容量不足、動態容量與錯誤成功 |
| 開發期邊界 | 容量、動態目錄、併發、失效注入及檔案系統／namespace 檢查 | 不能把單次開發檢查當成跨環境正式泛化 |
| 量測完整性 | 正式資料未出現已定義的無效列舉；部分失效注入能拒判 | 底層探針遺失、反向載入順序、其他掛接方式 |
| 時序方法比較 | 同一 VM 環境分開收集一次；有原作者流程與結果驗證 | 共同記錄開機 ID、環境與宿主負載的多開機比較 |
| 磁碟視圖工具 | Decloaker 九次開機、720 次掃描，反映完整路徑解析與父目錄列舉的差別 | 其他功能及隱藏模型；rkchk 相容核心的實測 |
| 成本 | 大目錄完整方法約原始列舉 4.76 倍；摘要邏輯資料量固定 | 各步驟成本、實際配置記憶體與輸出流量、多環境成本 |

主實驗只含一部 Ubuntu 22.04.5 虛擬機、Linux `6.8.0-138-generic`、ext4 與靜態目錄。受控模組決定預期差異，目前最直接支持的是量測流程在受測條件下正確。

批次層級召回率的 Wilson 95% 區間為 99.34%–100%，誤報率為 0%–0.53%，計算假設批次獨立。每批 20 次列舉不獨立；九次開機全部成功的開機層級區間為 70.09%–100%。後續統計應以開機或獨立環境為重複單位，保留批次及列舉的描述值。

外部時序方法在四情境的函式／序列分組誤報率為 15.20%／27.18%，來自依測試標籤選最佳 F1 門檻的原作者流程；不能當成事前固定門檻的獨立驗證。本方法對應矩陣為另外收集的 1,000 批，無法確認兩方法在同一次開機。事後固定門檻的重分析也須標明其性質。

Decloaker 的 180 次隱藏掃描未警報，只支持受測功能與列舉隱藏模型的適用範圍差異，不能推論整個工具無效。早期結果文件中「尚未比較」等進度描述應連同後來的外部比較紀錄閱讀。

## 下一步與建議順序

### 第一階段建立跨環境量測證據

**先補量測可觀察性。** 在新版本與新資料中加入 kretprobe `nmissed` 的前後讀數，或說明核心無法提供時的處理；定義探針遺失是否使整次列舉無效。比較 eBPF 先掛與模組先載入，再加入另一種掛接機制，確認外層呼叫仍可觀察。

交付內容是載入順序與掛接方式的觀測矩陣，以及正常、遺失和不可觀測情形的紀錄。完成判準在收集前固定，至少要求已知量測失效不能被當成一致。這項工作尚未實作。

**接著固定跨環境規約。** 建議先選原核心與一個新核心、ext4 與另一個可行檔案系統，逐步加入 create/delete/rename 動態目錄，以及至少一個不共用 CARAXES 程式碼、且作用位置落在觀測範圍內的隱藏模組。先做相容性檢查，再凍結正式核心矩陣，避免一次擴成所有因素的完整組合。

交付內容是環境清單、獨立模組來源、固定規則、樣本數與成功條件。每次開機保存核心與發行版、掛載設定、工具鏈、程式雜湊、boot ID，以及宿主 CPU／記憶體負載；成功與失敗全部保留。動態目錄另行定義可接受的暫時差異，不能直接沿用靜態目錄的惡意解讀。

**同時設計外部方法重複比較。** 在共同情境與隱藏模組下，讓本方法與 Trace of the Times 分別執行，以免探針互相改變量測；輪替方法順序，跨多次開機重複，記錄可交叉核對的環境。分析前固定正常資料校準與批次聚合規則，原作者使用測試標籤選門檻的結果只能另列。

交付內容是跨開機結果、拒判率、各環境誤報率與召回率，以及以開機為單位的不確定性估計。這會回答目前的完美結果與單次比較差異能否重現。

**成本分析可與上述開發交錯進行。** 先拆分原始列舉、使用者端摘要、eBPF 掛接、名稱讀取、雜湊、IBLT 更新、讀回與解碼。使用同一流程、迭代數及環境做配對比較，保存宿主負載；除平均數外報告分布與尾端延遲。

再比較 4 倍、8 倍與動態容量的時間、邏輯資料量、實際記憶體和解碼失敗率。動態容量若需要重新列舉，必須標示新交易，不能把目錄已變動後的重掃視為原交易的完整還原。成本尚未拆解前，不把新增耗時歸因於單一元件。

第一階段完成後，才能對跨環境泛化、可操作成本與外部方法差異提出更強的結論。既有正式資料維持原樣；修正後的新方法用新版本與新鎖定資料驗證。

### 第二階段測試會針對量測器調整行為的攻擊者

比較有金鑰雜湊與目前 FNV-1a 的成本，先釐清核心已失陷時可保護哪些金鑰或量測資料。更換雜湊函式本身不能證明金鑰可保密。

建立已知種子下的碰撞與替換測試，以及辨識量測程式後只對它放行的測試模組。記錄何時能避開、何時被拒判，以及需要何種額外可信觀測。交付內容是明確的攻擊能力、成功條件與失效案例，不預設現有量測點能抵抗完整核心控制。

### 第三階段延伸行程隱藏與補充工具比較

先用靜態行程集合驗證 `/proc` 的觀測位置，再加入行程建立與結束事件作為不依賴 `/proc` 列舉的觀測。設計包含 PID 與行程生命週期識別的配對方式，處理 PID 重用、短生命週期行程與兩端觀測時間差。

交付內容是能區分暫時視圖差異與持續性隱藏的時間一致性規則，再逐步增加高頻率行程變動。這是新研究問題，不能直接把檔案列舉結果當成行程隱藏成效。

取得 rkchk 相容核心後再執行其支援的檢查，另評估 Decloaker 其他功能。各工具依自己的觀測邊界、相容環境與隱藏模型報告，不把不適用的功能記為一般偵測失敗。
